    Shown to the BLO and, in aggregate, to the public. Transparency means a BLO's own numbers are always visible, not just the final roll.

    Deletions need a second officer

    Rule: no deletion without a notice and a chance to be heard. The ERO proposes, and a different officer approves.

    The automated pipeline

    What a computer does on its own, and where a person must still decide. This is the backbone for transparency: every automatic step should log what it did and why.

      Hosting and deployment

      This page is static: no server, no database. A commit to the repository's main branch can auto-deploy it, so the public always sees the latest version. See .github/workflows/deploy-pages.yml for a ready-made GitHub Pages workflow.

      A backend for realtime updates

      The backend/ folder has a small Node server that simulates what integrating a real election database would look like: a REST API plus a WebSocket feed that pushes elector, deletion and activity updates live, instead of this page's in-memory demo data. Run npm start inside backend/ and open its monitor page to see it. See backend/DEMO.md for a script to demonstrate it to stakeholders.

      Activity log

      Every change records who did it, what changed and when. In a real system this log would be append-only.
